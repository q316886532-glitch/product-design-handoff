# Architecture And Open-Source Evaluation Rubric

Use this when choosing architecture, libraries, frameworks, hosted services, or open-source projects.

## Evaluation Criteria

- Fit: directly supports the product's required workflow.
- Maturity: stable releases, active maintenance, clear ownership.
- Integration cost: compatible with the existing stack and deployment target.
- Extensibility: can support likely near-term requirements without heavy rewrites.
- Operational burden: acceptable hosting, monitoring, security, and upgrade effort.
- Licensing: compatible with intended use.
- Data/control: acceptable privacy, portability, and vendor lock-in profile.
- Community and docs: enough examples, issue activity, and documentation for Codex-assisted development.

## Research Expectations

- Prefer official docs, repositories, release notes, and primary sources.
- Check recency for active libraries and hosted services.
- Compare at least two plausible options for high-impact choices.
- Record the chosen option, rationale, rejected alternatives, and risks in `docs/03-Architecture-Spec.md` and `docs/05-Decision-Log.md`.
